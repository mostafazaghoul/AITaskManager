# AI Task Manager

A REST API for managing tasks, built with FastAPI. Tasks are automatically categorized and prioritized by GPT-4o mini, and the API can parse plain English input like *"urgent report due Friday"* into a structured task.

## Features

- **Full task CRUD** — create, read, update, delete with proper HTTP status codes
- **Natural language input** — parse *"dentist appointment tomorrow at 2pm"* into a structured task via `POST /ai/parse`
- **Auto-categorization** — every new task is classified into Work / Personal / Learning / Health / Finance / Home / Other by GPT
- **Priority inference** — GPT infers High / Medium / Low from urgency language in the input
- **Daily planner** — `GET /ai/plan/daily` returns a GPT-generated schedule that prioritizes High-priority tasks first
- **Overdue summary** — `GET /ai/summary/overdue` lists all incomplete tasks past their due date
- **Web UI** — served at `/`, no separate frontend server needed
- **Interactive API docs** — Swagger UI at `/docs`, auto-generated by FastAPI

## How It Works

### Architecture

Each layer has a single responsibility:

```
app/
├── main.py              # App setup, router registration, serves the UI
├── database.py          # SQLAlchemy engine and session
├── models.py            # Database schema (ORM models)
├── schemas.py           # Request/response shapes (Pydantic)
├── crud.py              # Database queries — no business logic
├── routes/
│   ├── tasks.py         # CRUD endpoints
│   └── ai.py            # AI endpoints
└── services/
    ├── parser.py        # Natural language → structured fields
    ├── categorizer.py   # Task title/description → category label
    └── planner.py       # Task list → daily schedule
```

A request flows through: **Route → Service (if AI) → CRUD → Database**, with Pydantic validating inputs and outputs at the boundary.

### AI Features

**Natural language parsing** (`POST /ai/parse`) sends the raw text to GPT with the current date/time as context, and asks it to return a JSON object with `title`, `description`, `due_date` (ISO 8601), and `priority`. The result pre-fills the web UI form so the user can review before saving.

**Categorization** runs automatically after every `POST /tasks/`. The task is saved first, then GPT picks one of seven category labels. If the API call fails, the task keeps its default `Uncategorized` label — the AI is an enhancement, not a dependency.

**Daily planning** (`GET /ai/plan/daily`) formats all incomplete tasks — including their priority and due date — into a prompt and asks GPT to produce a time-blocked schedule with High-priority items scheduled first.

## API Reference

### Tasks

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/tasks/` | Create a task |
| `GET` | `/tasks/` | List all tasks |
| `GET` | `/tasks/stats` | Completion rate and breakdowns by priority and category |
| `GET` | `/tasks/{id}` | Get a single task |
| `PUT` | `/tasks/{id}` | Update a task |
| `DELETE` | `/tasks/{id}` | Delete a task |

### AI

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/ai/parse` | Parse natural language into structured task fields |
| `GET` | `/ai/plan/daily` | Generate a prioritized daily plan |
| `GET` | `/ai/summary/overdue` | List overdue incomplete tasks |

**Create a task:**

```bash
curl -X POST http://localhost:8000/tasks/ \
  -H "Content-Type: application/json" \
  -d '{"title": "Read Clean Code", "description": "Chapter 3", "priority": "High", "due_date": "2026-06-01T09:00:00"}'
```

```json
{
  "id": 1,
  "title": "Read Clean Code",
  "description": "Chapter 3",
  "due_date": "2026-06-01T09:00:00",
  "priority": "High",
  "completed": false,
  "category": "Learning",
  "created_at": "2026-05-14T10:22:31.004"
}
```

**Parse natural language:**

```bash
curl -X POST http://localhost:8000/ai/parse \
  -H "Content-Type: application/json" \
  -d '{"text": "urgent client call tomorrow at 3pm"}'
```

```json
{
  "title": "Client call",
  "description": null,
  "due_date": "2026-05-15T15:00:00Z",
  "priority": "High"
}
```

## Getting Started

**Prerequisites:** Python 3.11+, an [OpenAI API key](https://platform.openai.com/api-keys) with billing enabled.

```bash
git clone https://github.com/mostafazaghoul/AITaskManager.git
cd AITaskManager

python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# Add your key to .env: OPENAI_API_KEY="sk-..."

uvicorn app.main:app --reload
```

- Web UI → `http://localhost:8000`
- API docs → `http://localhost:8000/docs`

## Design Decisions

- **Layered architecture** — routes, services, CRUD, and models are fully decoupled. Swapping SQLite for PostgreSQL or a different LLM requires changing one file each.
- **AI as an enhancement, not a requirement** — categorization fails gracefully; the rest of the API works without an OpenAI key.
- **`gpt-4o-mini` for all AI features** — fast and cheap enough for real-time use ($0.15 / $0.60 per million tokens), with quality sufficient for classification and short-form generation.
- **Mocked tests** — external API calls are patched at the service boundary, keeping the test suite fast and runnable in CI without secrets.
